# 003 GTE（COP2）

狀態：`READY`

## 1. 範圍

GTE 的 64 個暫存器（資料 r0–r31、控制 r32–r63）的寫入與讀回語意，以及 22 個有效命令。
不含 CPU 端的 `MFC2`／`MTC2`／`CTC2`／`CFC2`／`LWC2`／`SWC2` 延遲與 pipeline 時序，
那屬於 `004-cpu-r3000a`。

套件：`internal/gte/`。不依賴 CPU、匯流排、BIOS，可單獨驗收。

## 2. 介面

```go
type GTE struct { /* 內部狀態 */ }
func (g *GTE) Write(reg int, v uint32)   // reg 0..63；0..31 走 MTC2 語意，32..63 走 CTC2 語意
func (g *GTE) Read(reg int) uint32       // reg 0..63；MFC2／CFC2 語意
func (g *GTE) Execute(cmd uint32)        // COP2 命令字，只看低 25 位
```

## 3. 驗收語料

`JaCzekanski/ps1-tests` commit `f727802fead11f1daa7549285548392ef87749cb`
的 `gte-fuzz/gte_valid_0xc0ffee_50.log`（MIT），實機產生。
`tools/fetch_ps1tests.sh` 抓到 `testdata/ps1-tests/`，sha256
`4577214dec452509eb5e8f3ff4c120d50bb361db13381ce9fee8bad2b3520421`。

| 項目 | 值 |
|---|---|
| 筆數 | 1150 |
| 命令 | 22 個有效命令各 50 筆（AVSZ3、AVSZ4 各 50），外加 0x40 的 50 筆 |
| 每筆內容 | 64 個寫入值（`> r[i] = 0x...`）、命令行、64 個讀回值（`< r[i] = 0x...`） |

### 3.1 產生程序（依原始碼，confirmed）

依 `gte-fuzz/main.c` 的 `fuzzCommand` 與 `gte.s`：

1. 依序 `i = 0..63` 寫入：`i < 32` 用 `MTC2`，否則 `CTC2`。紀錄的是**寫入值**，不是寫入後的狀態。
2. 若命令不是 0x40，執行一個 COP2 命令。命令字 = `(c & 0x1FFFFFF) | 0x4A000000`，
   `c` 的位元欄（`gte.h` 的 `union Command`）：

   | 位元 | 欄位 |
   |---|---|
   | 0–5 | cmd |
   | 10 | lm |
   | 13–14 | tx（MVMVA 平移向量） |
   | 15–16 | vx（MVMVA 乘數向量） |
   | 17–18 | mx（MVMVA 矩陣） |
   | 19 | sf |
   | 20–24 | 0 |

   命令行格式：`GTE 0x%02x NAME (sf=%d, lm=%d, tx=%d, vx=%d, mx=%d)`。
3. 依序 `i = 0..63` 讀回並紀錄。

0x40 那 50 筆不執行命令，只測寫入與讀回的副作用（例如寫 r15 推進螢幕座標 FIFO、
唯讀暫存器、讀回時的符號擴展、FLAG bit 31 由其他位元算出）。

### 3.2 判準

1150 筆的 64 個讀回值**全部**相符。實作順序：先過 0x40 的 50 筆，再逐一命令。
