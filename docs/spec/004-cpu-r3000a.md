# 004 CPU（R3000A）

狀態：`DRAFT`

## 1. 範圍

MIPS I 整數指令、load delay slot、branch delay slot、COP0 例外與中斷、
隔離快取寫入（BIOS 用來清快取）。不含記憶體映射與匯流排時序（另立規格）。

## 2. 為什麼還不能 READY

找不到逐指令、實機產生的 R3000A 語料（2026-10-15 以網路搜尋與 GitHub 搜尋查過）。
可用的語料都是 PS-EXE，要 BIOS、匯流排、TTY 輸出才跑得起來：

| 語料 | 授權 | 預期輸出 | 備註 |
|---|---|---|---|
| ps1-tests `cpu/cop` | MIT | `psx.log`（實機） | 協處理器停用／無效命令的例外 |
| ps1-tests `cpu/access-time` | MIT | `psx.log` | CPU＋匯流排時序，兼作匯流排 oracle |
| ps1-tests `cpu/io-access-bitwidth` | MIT | `psx.log` | 對各 IO 用不同寬度寫入，兼作匯流排 oracle |
| ps1-tests `cpu/code-in-io` | MIT | `psx.log` | 從 scratchpad 與 IO 區執行程式碼 |
| amidog `psxtest_cpu`、`psxtest_cpx` | zip 條款未寫；wiki 內容為 CC BY-NC-SA 3.0 | 未知（推測畫面輸出） | 只抓進 `testdata/` 本機用，不散布 |

所以 CPU 的「全部通過」判準依賴機器層，驗收歸到「最小機器」里程碑（`001-scope-and-mvp` §4 M2）。

## 3. 驗收（暫定）

- ps1-tests `cpu/*` 的 TTY 輸出與 `psx.log` 逐位元組相同（`psx.log` 以 `% ` 開頭的行是 TTY 輸出，
  比對規則進 READY 前要從原始碼確認）。
- amidog `psxtest_cpu`、`psxtest_cpx` 全部通過（輸出方式待確認）。
- 在那之前，`internal/cpu/` 用依 psx-spx 寫的手寫測試開發。手寫測試是拿自己驗自己，不能當驗收。

## 4. 進入 READY 前要補

- TTY 攔截點：從 psx-spx 的 BIOS Function Summary 查 putchar／std_out 的 A0h／B0h 函式編號，
  不憑記憶寫。
- delay slot 與例外交錯的邊界案例清單。
- 時間基準：見 `001-scope-and-mvp` §3.1。
- 主要參照 `beetle-psx-libretro` 的 `mednafen/psx/cpu.c`（GPL-2.0-or-later）。
