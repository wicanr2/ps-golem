# 025 HD 主輸出與原生繪圖按需生成

狀態：`DRAFT`。HD主輸出與原生像素接管只允許研究探針；§9原生顯存觀測封裝及§11正式相容平面接線已獨立CONFORMED，其他圖文交易仍DRAFT；尚未換進本機可玩候選。使用者於 2026-10-25 授權繪圖接管，要求避免原生與 HD 重複繪製，並進一步擴大實際可見場景。相關遊戲工作由素材專案 Issue #13 與 #3 列管。本規格不將解析度放大當成視野擴大。

## 2. 本輪研究與限制

私人素材專案的 `tools/probe_native_render_contract.go` 沿用已保存的 DRE 原函式 GP0，保留受控貼圖上傳，不啟動遊戲、不載入 HD 美術。輸入、原始碼及工具雜湊保存在其 `workplace/render-control-v1/`，原命令與影像不放本公開儲存庫。

一次有效負對照包括 226 個命令封包、167 個原生精靈。略過精靈後 GPUSTAT 相同，但原生 VRAM 相差 25921 個字，完整 GPU 狀態不同。後加的受控 GPUREAD 與 VRAM 複製均顯露差異。首次研究工具因未列入單字快取清除命令而停止，保留失敗來源後補齊解析；不是產品缺陷。

這只否定「直接省略精靈仍然等價」。沒有觀察正常 DRE 是否發出這些讀回、沒有測正常路線的需求頻率、沒有完成延後生成，也沒有量測 FPS。現有素材、正常遊玩與寬視野證據依各自規格承接，不重跑美術。

## 3. 候選接管契約

候選方向是在 HD 模式保留原生命令與必要狀態，僅在確定需要原生像素時生成。這是待驗證設計，不是已選定的資料格式或可直接實作的介面。

- 原生模式及停用接管時維持現有同步光柵化，沒有遊戲改字。
- 一般 HD 模式不改 CPU、RAM、週期、GP0／GP1 狀態、IRQ、DMA 或記憶卡。未知原生讀寫依賴先走原路徑。
- 原生讀回、貼圖回授、VRAM 搬移、背景混色、遮罩、快取、克隆及摘要須取得與同步版本相同的原生結果。
- 命令記錄要有界，保存當時的繪圖／掃描狀態與順序，不能因之後的 GP1 重設或 field 改變重播出不同結果。
- 不從 HD 重繪、色彩校正、濾鏡或縮圖反推原生 15-bit 字與半透明位元。
- 呈現交易完成與來源有效性另行追蹤。不得用永久保持舊畫面掩蓋未知素材，也不得宣稱省略原生運算會自動解決所有閃爍。
- 真正寬視野繼續走 `apps/sotn` 的 017 模式。原人物比例與角度保持，擴大送出與剔除範圍；保留原版模式及既有海報選項，不把海報填邊算成新場景。模式開啟仍適用 017 的決定性例外。

## 4. 升 READY 前的缺口

1. 已完成下節的正常NO3開機／讀檔／移動觀察；其他場景及切換仍需觀察。原生像素的讀取者、最後寫入與快取讀取分開記錄，受控後加命令不代替正常路線需求證據。
2. 盤點公開 VRAM 陣列與切片別名的所有觀察點，確立可攔截的同步介面或證明特定用途不會讀到未生成內容。不能在保留直接陣列存取時假設延後生成完全透明。
3. 驗證最小原生狀態的即時更新與像素工作的分離，涵蓋多邊形自帶 TPage、折線串流、命令取消、快取、隔行及半透明回授。
4. 比較有界命令重播、區域依賴與既有同步回退的成本。沒有需求頻率及成對量測前，不宣稱固定加速倍數。
5. 為已證實且範圍有限的替代路徑補齊輸入、狀態、邊界及負對照，再將該切片升 READY。其餘維持 DRAFT，不用猜測補洞。

## 6. 正常路線的原生像素需求

私人素材專案的tools/prepare_native_demand.py與observe_native_demand.go只用原始碼覆蓋增加觀察，不改正式GPU。兩次獨立BIOS／同卡開機，沿既有正常按鍵至field8330；5200、5600、6000、6400四點符合既有正常摘要。七個檢查點的完整RAM、原生GPU、CPU GPR及摘要、卡片一致。這是觀察中立性，不是成熟模擬器交叉oracle或新正常GUI。原版輸入與結果仍留私人本機。

最後8160至8330的正常遊玩區段，GPUREAD呼叫2430次但沒有VRAM像素讀回，Status呼叫5384次。貼圖快取填入的1953120個讀取中，18283個字的直接最後寫入者是原生圖元；54023個混色讀取也依賴圖元結果。色盤快取316048次沒有直接圖元來源；本區段未見VRAM複製、遮罩像素需求。另有170次填色、958次上傳與958次清快取。這些計數不能把全遊戲原生讀回判為零，也不能把GPU資訊查詢當成像素需求。

追蹤只保留直接最後寫入者；沒有遞迴追蹤複製後代，快取命中不重算實體VRAM讀取，混色與遮罩是分開的語意理由。正式來源的直接觀察位置另列15處，含公開VRAM／切片、摘要、克隆、原生畫面、CPU與DMA讀回；未宣稱涵蓋外部持有的陣列別名。

結論限於此區段：即使沒有CPU像素讀回，也不能空跳原生圖元。候選設計須保留貼圖回授與混色，可研究由GPU維護一倍原生相容平面，與HD主畫面分工；既有一倍HD後端的VRAM／快取與完整原生狀態已接續本規格§8的限定研究；此批尚未接正式觀測介面與HD4主畫面；後續§9完成純觀測封裝、§10完成研究同掛，整體架構仍未升READY。一般查詢不應為未知像素需求被迫同步，原生API與時序契約仍是升READY前條件。

本輪原cue為Big5且引用原大寫檔名，研究準備工具誤按UTF8解碼而停於執行前；修正為internal/disc.Open已確認的同目錄唯一BIN回退，未改cue／BIN。保留停止目錄後正常觀察有效執行一次，沒有重跑既有美術矩陣或正常GUI。狀態保持DRAFT。

## 8. 原生解析器與一倍相容像素平面的研究

狀態：DRAFT，限定原型研究已驗證，正式路徑未改。NATIVE-PLANE-20261026的來源基準為35a9dc455cf448301a9a61b15383f53de7bec43c。只在相鄰素材專案的Go覆蓋接線，工具入口為其tools/prepare_native_plane.py、probe_native_plane.go與accept_native_plane.py，收據在workplace/render-control-v1/native-plane-v1/。沒有新原版routine、素材或存檔格式。

### 8.1 實際分工

- 原生端繼續命令解析、GPUSTAT、IRQ、掃描時序、上傳／讀回游標、多邊形自帶TPage與折線狀態。略過精靈、線段、多邊形、填色、複製與上傳的像素工作，不空跳整個命令。
- 一倍影子不掛美術、不用PGXP／透視／寬視野，重播原始GP0／GP1及原生場奇偶，供應精確RGB555/STP、CLUT與貼圖快取。CPU／既有GPU光柵裝置分開驗證；這不是從HD重繪縮回原圖。
- 顯示影子的C0執行只清貼圖快取，沒有啟動CPU讀回游標。首次原型在第三例取得0，與原生001f8001不同而停止。研究覆蓋才接既有fbReadStart，並在CPU像素讀回時同步消費一倍平面的ReadData。不得把這個新角色直接套用一般HD主影子。
- 明確觀測與完整Clone先同步VRAM及CLUT／貼圖快取；研究計數、影子指標只從Clone排除，其他完整原生GPU狀態比較不忽略。每封包或正常field採阻塞fence，未改正式影子佇列。

### 8.2 已取得證據

CPU共21組，前兩組證據承接、只重建必要前綴，C0與其他19組為新檢查。GPU同一新相容角色21組全通過。包含環繞上傳、奇數讀回、TPage、折線、取消／重設、CLUT舊快取、明確清快取、四種STP混色、遮罩、貼圖回授、複製、隔行與克隆隔離。每個輸入字的GPUSTAT／IRQ、讀回值及完整GPU／像素快取在同步後與原生CPU基準相同。原始停止來源／二進位／日誌保留，不將Xvfb收尾訊息當產品缺陷。

GPU角色實際工作為三個三角形、25精靈、2568像素、兩次CPU回退及11次回讀。這批是LIBGL_ALWAYS_SOFTWARE=1的Mesa llvmpipe，不是新實體GPU或速度驗收，既有021硬體證據按原範圍承接。

另一次正常兩機由真BIOS／同卡開機，讀檔、移動、跳躍至8382。1200／4320／5200／6000／8160／8293／8382七點完整RAM、原生GPU含CLUT／貼圖快取、摘要與卡片一致。控制端略過562672精靈、2862線段、98887多邊形、6267填色及10692426個32位元上傳資料字的像素處理；精確相容像素由一倍CPU平面計算。沒有省掉所有原生像素運算或加速聲明。這批尚未驗正常GPU平面與HD4主畫面同掛；該研究缺口由§10接續。GUI、其他場景及通關仍未驗。

### 8.3 下一個正式接線閘門

CPU與GPU的直接公開VRAM陣列負控制都顯示同步前內容過期，證明原型尚不能透明取代正式GPU。必須先收束Machine.VRAM、摘要、原生Screen、Clone、CPU／DMA讀回與外部持有別名的觀測契約，不能只在測試前手動同步。

目前正式來源的原生陣列直接讀寫集中在internal/gpu的power／texel／put／plot／Screen及machine的VRAM／Digest，psexe經Machine.VRAM輸出；影子自己的VRAM另行處理。這份來源盤點不能證明外部長期別名不存在。下一切片先封閉觀測／別名，保持原版模式與HD4主畫面、CPU／GPU選擇，再接正式相容平面；證據未齊不開啟候選。整體025仍DRAFT，完整HD與其他美術工作保持原範圍。


## 9. 原生顯存觀測封裝

狀態：CONFORMED，僅限本節觀測封裝。025其他部分維持DRAFT，沒有在正式路徑啟用原生像素分工。NATIVE-DUAL-OBSERVERS-20261026來源為5da8162；相鄰素材專案native-dual-v1/observer-READY-v1.json固定輸入SHA與驗收範圍，engine-input-source-v1.tar保存完整追蹤來源，進行中的已編譯研究不受後續Go來源編輯影響。

### 9.1 已確認的問題與契約

原生GPU的公開VRAM陣列及Machine.VRAM的切片可能被長期持有。前批CPU／GPU負控制都證實替代像素路徑同步前會過期。新研究以私有陣列、獨立快照及自動觀測同步通過CPU／GPU各三組雙平面契約；舊公開陣列程式被編譯器拒絕。此證據支持先封閉觀測入口，不授權直接啟用未驗完整的後端。

- internal/gpu.GPU的原生VRAM改為私有，內部光柵化仍直接讀寫相同固定陣列，不新增像素熱路徑的函式呼叫、掃描或等待。
- 新增GPU.VRAMSnapshot()，每次回傳1024×512個原生uint16字的獨立副本，包含RGB555與bit15；全零、半透明黑色與其他原字精確。回傳值由呼叫者持有，修改或長期保留不影響機器，也不跟隨之後繪圖變動。
- Machine.VRAM()維持[]uint16介面與讀取時點，改用上述快照。既有「觀測用、勿改」契約可繼續使用；寫入仍經既有GP0命令。psexe的VRAM輸出沿Machine.VRAM，Digest消費同一快照入口。
- 原生Screen與Clone、CPU／DMA讀回保留目前同步語意；現行正式路徑尚無延後像素，不增加研究同步器或替代平面。未來接線須沿§8的自動同步契約，再取得獨立READY。
- render/hd.Renderer自己的VRAM與既有CPU／GPU呈現路徑不變。GPUSTAT、IRQ、命令、CLUT／貼圖快取、CPU週期、RAM、記憶卡與存檔不改。

### 9.2 實作與驗收

入口為internal/gpu/vram.go、machine/machine.go與machine/digest.go，原生光柵化只調整欄位可見性。套件內部fixture改用私有欄位；render/hd/affine_test.go的跨套件原生取樣改用快照。153份追蹤Go來源已盤點，觀測入口以本節為準，原始來源與每筆SHA可回查READY收據。

## 11. 正式原生相容平面接線

### 11.1 角色、輸入與觀測

- render/hd新增NativePlane，建構時固定一倍、無素材／PGXP／透視／寬視野，封裝私有Shadow及相容角色。可選既有CPU或GPU光柵裝置；角色不能被當成HD主影子，外部不能切換其素材／比例。
- 原生GPU在第一筆輸入前接上NativePlane，GP0／GP1及場奇偶各送一次。精度與素材場資訊只送主影子。原生端保留命令解析、GPUSTAT、IRQ、時序、TPage、折線與上傳／讀回游標；精靈、線段、多邊形、填色、複製、上傳像素由相容平面承接。C0僅相容角色啟動讀回，原生ReadData維持自己的游標與readBuffer。
- NativePlane.Snapshot輸出1024×512原生字、256字CLUT及256行貼圖快取的值副本。原生Screen、VRAMSnapshot、完整Clone／Digest及卸下前自動同步；讀回同步消費相容角色。原生資訊與狀態查詢不強制像素同步，不能從HD新稿反推原生字。Clone清掉呈現／相容指標及診斷計數，保留完整原生機器狀態。
- 不掛相容平面時走既有同步光柵化。卸下時先同步像素與快取，再恢復同步原路徑，不能漏掉累積圖元。接上空白平面只限上電前；拒絕覆蓋已掛平面。診斷計數不參與遊戲規則或存檔。

### 11.2 有界工作與所有權

NativePlane由機器執行緒寫入及關閉，最多累積4096個GP0／GP1／場事件後阻塞fence，避免無頭流程無限堆積。主影子的既有前端一場呈現界線保持；RequestFence與非同步畫面完成通知須等待主影子及相容平面都完成先前輸入，不讀回完整像素。不得讓影子回呼直接操作Machine。

前端HD啟用時配置主影子及獨立NativePlane。CPU選擇兩者均CPU；GPU選擇兩個獨立GPU裝置，auto建立失敗可沿既有規則回退CPU，明確gpu建立失敗須報錯。裝置由各自消費端關閉，不共用VRAM或關閉同一裝置兩次。正常停止先停止機器輸入、保持圖形服務可用，卸下／同步相容平面，然後Close兩個消費端及原session。若圖形主迴圈異常終止，沿既有Cancel釋放等待，只做終止收尾，不接受此時讀回像素或繼續執行該機器。
