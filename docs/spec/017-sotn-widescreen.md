# 017 《月下》寬螢幕 16:9

狀態：`DRAFT`（只允許研究與可丟棄的 probe）

## 1. 為什麼不能是 GPU 後端選項

`016` §1 要求 HD 不改變決定性狀態。《月下》以 2D 為主，畫面外的敵人、物件、背景圖塊遊戲本來就不送給 GPU，
影子 GPU 再怎麼放大也畫不出來。第三方 PC 重編譯版的 16:9 是改遊戲的繪圖與剔除邏輯做到的，
部分背景只做了 4:3 的範圍，部分全螢幕效果仍在原框內
（Generation Amiga 2026-07-11〈Castlevania: Symphony of the Night PS1 recomp adds native 16:9 widescreen〉）。

結論：寬螢幕必定改寫遊戲的 RAM 或程式，屬遊戲修改，放 `apps/sotn`，不放 GPU 核心。

## 2. 與決定性的關係（待使用者決定）

| 方案 | 內容 |
|---|---|
| A. 遊戲修改模式 | `psgolem -widescreen` 開啟時套用 `apps/sotn` 的修改。開啟期間不保證與原版重播一致：不產生 `psexe` 摘要、不用於 M4 這類驗收、不用於觀測 API。記憶卡照常讀寫 |
| B. 不做 | 16:9 視窗只做左右補黑（現況） |

`AGENTS.md` 目前把 HD 定為不得改變決定性狀態的 GPU 選項；選 A 要先修改該條，把遊戲修改模式列為例外。

## 3. 要找出的機制

| 項目 | 問題 |
|---|---|
| 顯示範圍 | GP1 06h／07h 的水平範圍與繪圖區寬度；加寬後的 framebuffer 在 VRAM 裡會不會蓋到貼圖頁 |
| 鏡頭 | 房間捲動座標、鏡頭跟隨玩家的置中與邊界夾限 |
| 背景圖塊 | 每層圖塊送 GPU 的欄數與起點，能否多畫左右各一段 |
| 實體剔除 | 實體在畫面外時停止繪製或停止更新的邊界值；只放寬繪製，不改更新，避免改變遊戲邏輯 |
| HUD 與選單 | 生命值、地圖、選單的位置是否以螢幕寬度計算 |
| 全螢幕效果 | 淡入淡出、轉場遮罩的矩形大小 |

## 4. 證據來源

- `Xeeynamo/sotn-decomp`（AGPL-3.0，`002` §3）：只查位址與資料結構，不搬程式碼。
  支援的版本為美版 SLUS-00067、`hd`（未發行的日文版）、`pspeu`、Saturn，**沒有日版 SLPM-86023**。
- 本光碟是 SLPM-86023 的中文化版。`015` §4 已以 RAM 差分核對實體表等位置與美版相同，
  但程式位址不能沿用：每個要改的函式都要用位元組簽章在本光碟的執行檔或 overlay 裡恰好找到一次再釘位址
  （`~/.claude/knowledge-base/retro/retro-remake-source-selection-and-byte-signatures.md` §二）。
- 中文化改了哪些檔案仍未知（`001` §6）。

## 5. 升級成 READY 的條件

1. 使用者在 §2 選定方案。
2. §3 每一項都有位址、位元組簽章與執行時證據（改值後的截圖對照）。
3. 確認加寬後的 framebuffer 不會覆蓋遊戲使用中的 VRAM 區域，或找到可行的位移方式。
